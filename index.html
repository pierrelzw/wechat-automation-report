背景

由于产品特点，小助手每月要负责大量的用户运营操作，包含拉群、批量发消息、转发卡片类信息等等。这每一步操作都是人工进行，比如一次拉群，需要人工操作鼠标键盘 16 次，且需要在石墨文档、微信等多个 app 之间切换，新手极易出错。

小助手们不得不加班，但人力依然不足，需要每周征集其他团队同学支持，在原本 4x7（预估）=28 人天的基础上，还需要额外耗费费 4-5 人天。如果维持现状，参与训练营的用户进一步增加，将需要等比增加更多人力支持，边际成本极高。

效果

支持了开营期间的绝大部分重负荷的小助手运营工作，比如新老用户入群、给新用户群发消息；

一个人+一条命令，即可支持数十个小助手账号（理论上）的以上工作；

6 月开始，开营期间不再需要征兵，小助手的加班时间也下降；

并且，用户运营的成本，不会随着用户数等比增加，边际成本极低。

功能说明

微信 + 企微自动化框架，支持三种工作流：

  • 批量邀请 (invite)：批量邀请联系人进群，同群多人合并为一批（每批人数默认 20，可调：config.json 的 invite.max_batch_size，或单次运行加 --invite-batch-size N）
  • 批量发消息 (send)：批量发送消息给联系人/群聊
  • 批量转发 (forward)：把公众号文章卡片以卡片形态批量「逐条转发」给联系人（每批最多 9 人）

在每个工作流的基础上，叠加了一下特性，以确保工作流稳定运行，出错时也知道如何处理：

  • 多账号支持：支持多个微信/企微，可自动切换不同账号实现以上功能（只支持串行）
  • 风控预防：实现了很多拟人操作，尽可能避免被发现自动化（但无法确保，控制数量很重要）
  • 生产模式：执行除最后一步的全流程，确认没问题以后再开始正式的 “生产流程”
  • 错误检测：支持发现执行过程中因为用户信息、网络、人工误触鼠标键盘导致的错误，及时标记人工处理，
  • 人工中断：如发现异常，可人工按快捷键 SHIFT+ESC 中断
  • 错误重试：如发现错误，可用 --retry-failed 或者 --resume 重试（详情见后续章节）
  • ……

本方案主要用 MacOS

appscript（系统操作）默认人工操作鼠标+键盘，不尝试 hack App 内部。

这可以尽可能避免风控，但也会增加开发难度，且每个环节的状态检测需要靠截图+OCR 识别实现，可能网络影响导致截图时机不对，无法实现 100% 成功率。

支持哪些客户端

本工具同时支持微信和企业微信 (WeCom)，但不是每种工作流都两边都能跑：

工作流微信企业微信企业微信要做的额外准备
批量邀请 invite✅✅填 apps.com.tencent.WeWorkMac.invite.add_button_offset 坐标；需开启 OCR。见「在企业微信上批量拉群」
批量转发 forward✅✅填 apps.com.tencent.WeWorkMac.forward 的窗口/框选几何。见「在企业微信上转发」
批量发消息 send✅❌ 未适配—

⚠️ send 请勿在企业微信上运行。 工具不会拦截这个组合：加了 --wechat-bundle-id com.tencent.WeWorkMac 照样会跑，但发送流程用的仍是微信的窗口标题和按钮文案，结果不可预期。

企业微信的多开分身（com.tencent.WeWorkMac1、com.tencent.WeWorkMac.clone1 等）按家族自动识别，与主实例享受同一份配置。

风控预防

  • 不碰接口，只操作界面：不使用非公开接口、不注入进程、不改客户端文件、不伪造网络请求。
  • 点击位置随机：在目标坐标上叠加正态分布偏移（按轴 ±5 像素），不会每次都精确点在同一像素。
  • 等待时长随机：全流程约 78 处等待均为「基准值 + 随机抖动」，无固定节拍。
  • 逐人循环零鼠标：选人纯键盘完成，重新聚焦弹窗用辅助功能接口而非点击。
  • 同群只开一次邀请窗口：同群多人合并为一批，窗口开合次数少一个量级。
  • 不做拟人化假动作：无随机鼠标漫游、无意义滚动、假装犹豫的停顿——收益不明确且拖慢运行。
  • 不自动限速：每批之间停不停、一天拉多少人由你决定，见下方「注意事项」。

⚠️ 以上降低的是「看起来像脚本」的程度，不等于保证不被限制。真正决定风险的是使用强度，请从小批量开始。

适用范围

邀请功能适用于以下场景：

  • 群聊邀请需要群主同意
  • 邀请人非群主
  • 群聊人数 > 50

✨ 新功能：SHIFT+ESC 快速退出

  • 🛑 随时按 SHIFT+ESC 立即停止自动化流程
  • 🔒 全局快捷键，任何界面都能响应
  • 💾 自动保存已完成的任务记录
  • 🧹 自动清理资源，无进程残留

🔬 Dry-Run 模式

  • 测试模式：使用 ESC 关闭邀请窗口，不点击邀请按钮
  • 生产模式：点击邀请按钮完成邀请
  • SHIFT+ESC 可用于取消整个流程
  • --dry-run 与 --yes 正交：--yes 只跳过确认弹窗，不会覆盖 dry-run。--dry-run --yes 仍然只移动到邀请按钮坐标后按 ESC，不会真正发出邀请，可安全用于自动化测试。
  • result CSV 含 dry_run 列：dry-run 行写入 dry_run=true，真实运行行留空。dry-run 行在下次运行时始终被视为待处理（不论 status），所以 dry-run 之后跑真实模式不会被旧"success"误判跳过。scripts/analyze_logs.py 也会自动跳过 dry-run 行。

系统要求

  • macOS 10.15 或更高版本
  • 微信 Mac 版 3.x 或 4.x（4.x 已实测 4.1.9 / 4.1.10）
  • 如果要在企业微信上跑 invite / forward：企业微信 Mac 版。企业微信的按钮坐标随屏幕分辨率变化且没有内置默认值，首次使用需按对应章节标定一次

说明：正常使用（运行邀请）不需要安装 Xcode / Command Line Tools。 只有在“开发机编译 helper / 重新打包发布”时才需要 Command Line Tools。

另外：核心自动化流程（invite / send 的发送本身）不依赖 Python。仅 send 工作流结束后自动生成的人工复核报告 review.html 需要 python3；目标机若没装 python3，发送照常完成，只是跳过该报告（日志会提示如何在有 python3 的机器上用 make send-review SESSION=<dir> 补生成）。

使用步骤

下面「第 1 步 打开终端」「第 2 步 授予权限」三种工作流（邀请 / 发消息 / 转发）通用；第 3 步起按你的任务看对应章节。本工具是纯命令行 (CLI)，每次运行都要在终端传入 CSV 路径。

第 1 步：打开终端并进入工具目录

  1. 按 Command + 空格，输入「终端 / Terminal」，回车。
  2. 输入 cd （cd 后留一个空格），再把解压出来的 wechat_automation 文件夹从访达拖到终端窗口——路径会自动补全，回车即进入工具目录。

第 2 步：授予权限（仅首次）

需要两项系统权限：

  1. 辅助功能（控制键盘鼠标）：系统设置 → 隐私与安全性 → 辅助功能 → 勾选你用的终端（Terminal / iTerm2）。
  2. 屏幕录制（检测窗口状态）：系统设置 → 隐私与安全性 → 屏幕录制 → 勾选你用的终端，勾选后需重启终端才生效。

不授予屏幕录制权限也能运行，但无法自动识别异常用户（ID 无效、已在群内），会全部按成功处理。

邀请（invite）操作步骤（照着做）

  1. 填好 CSV：编辑 invite_details.csv： ``csv inviter,wechat_name,wechat_id,target_group 邀请人名,备注名,微信ID1,目标群聊1 邀请人名,备注名,微信ID2,目标群聊2 `` > 也支持不含 inviter 列的旧格式（wechat_name,wechat_id,target_group）。
    • inviter: 邀请人名称，对应 config.json 的账号映射（多微信实例时必填）
    • wechat_name: 用户备注名（仅用于记录）
    • wechat_id: 要邀请的微信 ID 或备注名
    • target_group: 目标群聊名称（必须完全匹配）
  2. 先演练一遍（零风险）：只移动到邀请按钮就按 ESC，不会真正发出邀请： ``bash ./wechat_auto.sh invite --dry-run invite_details.csv ``
  3. 正式邀请：确认无误后，把 --dry-run 改成 --yes 再跑一次： ``bash ./wechat_auto.sh invite --yes invite_details.csv ``
  4. 看结果：终端会打印成功/失败数量与日志路径（详情见下方「查看结果」）。失败的行修正后可用 --resume 续跑、--resume --retry-failed 重试失败行。 > 🛑 运行中随时按 SHIFT+ESC（或 Ctrl+C）即可立即停止，已完成的记录会自动保存。

多微信实例配置（可选）

如果你有多个微信账号（多开），需要三步：

1. 做出微信分身（已经有分身可跳过）：

./clone-im.sh wechat      # 运行后询问要做几个
./clone-im.sh wecom 3     # 企业微信，直接做 3 个

脚本会复制一份完整的 App、改写 bundle ID、重新签名，做出可双击、能同时登录不同账号的分身，放在 ~/Applications/MultiWeChat（企微为 MultiWeCom）。编号沿用本工具的约定——微信从 com.tencent.xinWeChat2 起，企微从 com.tencent.WeWorkMac1 起——这样分身能自动套用对应 App 的配置。

每个分身都是完整复制一份 App，比较占磁盘；App 每次更新后分身会失效，重跑一遍脚本即可重建。全程不需要 sudo。

2. 查看已安装的微信实例及 bundle ID：

bin/wca-ax --detect-instances

输出示例：

INSTANCE_COUNT=2
INSTANCE=com.tencent.xinWeChat
INSTANCE=com.tencent.xinWeChat2

3. 编辑 release/仓库根目录（与 wechat_auto.sh 同级）的 config.json，映射邀请人名称到 bundle ID：

config.json 与 button_cache.plist 现在只从 release/仓库根目录读取、运行期只读（ADR-003 v2），不再使用 ~/Library/Application Support/wechat_automation/，也不会首次启动自动生成。config.example.json 仅作模板参考；按自己机器复制成根目录下的 config.json 后编辑即可。旧部署需把 ~/Library/.../config.json 移到根目录。

{
  "accounts": {
    "张三": "com.tencent.xinWeChat",
    "李四": "com.tencent.xinWeChat2"
  },
  "click_jitter": {
    "sigma": 2.0,
    "max_radius": 5
  },
  "invite_ocr": {
    "addButton_y_offset": -25
  }
}

click_jitter 段为可选项，控制 performClick 的鼠标抖动分布（正态分布、Box-Muller 采样、clamp 到 ±max_radius），降低自动化指纹用，正常情况下不要改。随发布包附带的 config.json 里是 σ=2.0、max_radius=5。

⚠️ 别把 max_radius 调大。它是按轴裁剪的（一个 ±N 的方框，不是半径），必须小于最小的可点击目标；企业微信「确认发送」弹窗的「发送」按钮只有约 24pt 高，早期的 5.0/12 会让点击落到按钮边框外、静默点空（issue #227）。

invite_ocr 段为可选项。邀请流程的 addButton（群信息侧栏的「+」加成员按钮）改为 OCR 优先定位：点击群信息后用 Apple Vision 识别「添加」文字标签，再向上偏移 addButton_y_offset（默认 -25，逻辑点，文字标签中心到「+」虚线框中心的距离）即为点击目标。OCR 未命中时无缝回退根目录 button_cache.plist 里的 addButton 预设偏移。addButton_y_offset 必须是 -500..500 的整数，超范围用默认 -25；启动时会打印生效值与覆盖键。运行期 plist 只读（ADR-003 v2）。若「+」点击反复落空，可微调 addButton_y_offset，或设 invite_ocr.enabled=false 回退到纯 plist 路径。

然后在 CSV 的第一列添加 inviter，工具会根据邀请人自动切换微信实例：

inviter,wechat_name,wechat_id,target_group
张三,备注名,微信ID1,群聊A
李四,备注名,微信ID2,群聊B

配好后照常运行即可（自动按 inviter 切实例）；也可用 --wechat-bundle-id 强制所有行用同一实例：

# 按 config.json 的 inviter 映射自动切换实例（推荐）
./wechat_auto.sh invite --yes invite_details.csv

# 手动指定目标实例（覆盖映射，所有行用同一实例）
./wechat_auto.sh invite --yes --wechat-bundle-id com.tencent.xinWeChat2 invite_details.csv

多开实例的精确 bundleId 只写在 accounts 里；apps 下保留 com.tencent.xinWeChat / com.tencent.WeWorkMac 这一份家族配置即可。微信路径不需要任何 apps 配置（默认行为不变）。

在企业微信 (WeCom) 上批量拉群

invite 可以直接跑在企业微信 macOS 客户端上。CSV 格式、批次逻辑、结果文件都和微信一样，只多三点准备。

1. 填「添加成员」按钮坐标

企业微信的按钮位置随屏幕分辨率变化，且没有内置默认值。打开 config.example.json，把 apps.com.tencent.WeWorkMac.invite.add_button_offset 整段复制进你的 config.json，键名就是程序日志里打印的屏幕指纹（如 1710x1107@2x）。缺坐标时该批次会失败，并在日志里提示要补的 key。

2. 确认 OCR 是开着的（invite_ocr.enabled 保持 true）

企业微信拉群路上有两个弹窗——大群/需审批群的「邀请」，以及开了「群聊邀请确认」的群额外弹出的「发送」——它们没有预置坐标，只能靠 OCR 认字定位。把 invite_ocr.enabled 关掉，这两步会直接失败。（微信路径关掉 OCR 只是回退到预置坐标，不受影响。）

如果你的客户端按钮文案和默认的不一样，改 config.json 里这两个键即可，不用重新打包：

"apps": { "com.tencent.WeWorkMac": { "invite": {
  "delayed_confirm_labels": ["邀请", "Invite"],   // 大群 / 需审批群的第二个弹窗
  "send_confirm_labels":    ["发送", "Send"]      // 群主开了「群聊邀请确认」时再多一个弹窗
}}}

3. 加 --wechat-bundle-id 参数

# 先演练
./wechat_auto.sh invite --dry-run --wechat-bundle-id com.tencent.WeWorkMac invite_details.csv
# 确认无误后正式拉群
./wechat_auto.sh invite --yes --wechat-bundle-id com.tencent.WeWorkMac invite_details.csv

⚠️ 企业微信的演练走不完全程。 企业微信里「确定」一按就不可逆地发出去了，所以 dry-run 在这一步只把鼠标移过去、不点击。也就是说：演练能验证 CSV、找人、选中这些环节，但走不到后面的「邀请」/「发送」确认步骤——演练全绿不代表这两步没问题。第一次在新机器上正式跑，建议先拿一个人、一个测试群试一次。

多开的企业微信（com.tencent.WeWorkMac1、com.tencent.WeWorkMac.clone1 等）用法与微信多开一致，见上一节。

查看结果

执行完成后会显示：

  • ✓ 成功数量
  • ✗ 失败数量
  • 详细日志文件路径
  • 失败任务 CSV（如有）

发消息（send）CSV 格式

推荐长表格式，支持给同一联系人按顺序发多条消息、按 inviter 切换微信实例：

inviter,recipient,seq,content,status
张三,客户A,1,你好我是志伟,pending
张三,客户A,2,"附注：今天, 明天都在",pending
李四,客户B,1,单条通知,pending
  • inviter: 发送人（对应 config.json 的实例映射；留空则用默认实例）
  • recipient: 联系人备注名/昵称（搜索框可定位）
  • seq: 同一 recipient 内的发送顺序（正整数）
  • content: 消息文本；含逗号请用双引号包裹，如 "今天, 明天"
  • 仍支持旧的短表格式 recipient,message,status（自动按单条消息处理）

当前仅面向个人联系人；群聊发送暂不支持。 同一 recipient 内某条失败后，后续消息标记 blocked：默认 --resume 跳过，--resume --retry-failed 时整组按 seq 顺序重发。

操作步骤（照着做）

  1. 填好 CSV：按上面的表头把要发的消息填进 messages.csv，存好。
  2. 先演练一遍（不真正发送）：会打开每个联系人的会话、粘贴消息，但不按回车发出（粘贴后自动清空）。用来确认每个收件人都能被搜到、会话能正常打开： ``bash ./wechat_auto.sh send --dry-run messages.csv ``
  3. 正式发送：确认无误后，把 --dry-run 改成 --yes 再跑一次： ``bash ./wechat_auto.sh send --yes messages.csv ``
  4. 核对 review.html：每条消息发送后都会截图存档，session 结束自动生成报告，逐条核对发送截图与内容（怎么打开见下方「查看 review.html 人工验收」；也可 make send-review SESSION=<目录> 手动补生成）。 > 🛑 运行中随时按 SHIFT+ESC（或 Ctrl+C）即可停止。send 不自动判断"是否真正送达"，最终请在微信里人工确认收件人确实收到。

转发（forward）CSV 格式

把已有的公众号文章卡片以卡片形态批量「逐条转发」给最多 9 个联系人。

⚠️ 关键前置：公众号卡片只能从一条已存在的卡片消息「转发」产生，无法用粘贴链接重建。所以先把本次要转发的卡片预置到一个「中转会话」（默认「文件传输助手」），该会话里只放这次要发的卡片和消息 —— 框选会扫到的都会被转发，别混入其它消息。

CSV 表头 inviter,recipient（推荐再带 wechat_name，便于在 review.html 里核对）：

inviter,recipient,wechat_name
,文件传输助手,我自己
,客户A,张三
  • inviter: 微信实例选择（同 invite/send；留空 = 默认实例）。同一 inviter 的多行合并成一批（每批 ≤9 人）
  • recipient: 收件人（联系人备注名/微信号/群名）
  • wechat_name: 可选，仅供 review.html 核对显示（微信名 ↔ 微信号），不参与搜索/发送

中转会话名由 config.json 的 forward.staging_chat 配置（默认「文件传输助手」）。

操作步骤（照着做）

  1. 准备中转会话：打开微信里的「文件传输助手」（或你在 config.json 里设的会话），把这次要转发的公众号卡片按顺序发进去，并确认里面只有这次要发的内容——框选会扫到的都会被转发，别混进别的消息。
  2. 填好 CSV：按上面的表头把收件人填进 forward_details.csv，存好。
  3. 先演练一遍（零风险）：在终端运行下面这条命令。它会真正打开「发送给」弹窗、逐人搜索+选中+截图，但不会真正发出（最后用 Escape 撤销），完全可逆： ``bash ./wechat_auto.sh forward --dry-run forward_details.csv ``
  4. 核对 review.html：打开生成的报告，逐人确认 微信名 ↔ 微信号 ↔ 选中截图 是否一致（怎么打开见下方「查看 review.html 人工验收」）。
  5. 正式转发：确认无误后，把上面命令里的 --dry-run 改成 --yes 再跑一次，即开始真正转发： ``bash ./wechat_auto.sh forward --yes forward_details.csv ``
  6. 人工确认送达：回到微信，确认收件人确实收到了卡片。

进阶：收件人来自生产 CRM xlsx 时，可先用离线转换器把 xlsx 转成 CSV 再人工核对，完整教程见 docs/forward-usage.md。

在企业微信 (WeCom) 上转发

forward 也能跑在企业微信 macOS 客户端上（invite 同样支持，见「在企业微信上批量拉群」；send 未适配，请勿使用）。交互步骤完全一样，只多两点准备：

  1. 填几何配置：企业微信的窗口/框选坐标和微信不同，且没有内置默认值。打开 config.example.json，把里面 apps.com.tencent.WeWorkMac.forward 整段（含你这台机器分辨率对应的 window_rect / select_drag_region，键名就是程序日志里打印的屏幕指纹，如 1710x1107@2x）复制到你的 config.json。没填的话整批会失败并提示要补的 key。
  2. 加 --wechat-bundle-id 参数：演练和正式转发都在命令里加上 --wechat-bundle-id com.tencent.WeWorkMac，例如： ``bash ./wechat_auto.sh forward --dry-run --wechat-bundle-id com.tencent.WeWorkMac forward_details.csv ./wechat_auto.sh forward --yes --wechat-bundle-id com.tencent.WeWorkMac forward_details.csv ``

中转会话同样默认「文件传输助手」（企业微信里也有）。按钮用 OCR 定位，无需逐机器调参。

选中校验分两层，先数字后截图：优先用 OCR 读弹窗顶部的「已选择 N 个」计数，每加一个人计数必须正好 +1 才算选中成功；读不到计数（光线、缩放、文案差异等）才回退到三点截图哈希比对。两层都判不出来时记为「可疑」交人工复核，不会当成功。

企业微信多开：和微信多开一样，企业微信多开成多个 app（com.tencent.WeWorkMac、com.tencent.WeWorkMac1…、com.tencent.WeWorkMac.clone1…）也支持——按家族识别，不再只认单个 bundle。用法同微信多开：CSV 加 inviter 列配 config.json 的 accounts，或用 --wechat-bundle-id 指定某个实例。accounts 里写精确 bundleId 来选择账号实例；apps 里只维护 apps.com.tencent.WeWorkMac.forward 这一份企业微信家族几何（window_rect / select_drag_region），所有 WeCom clone 会按 exact → canonical 顺序继承它。指纹键就是程序日志里打印的屏幕指纹（如 1710x1107@2x）。

查看 review.html 人工验收

send 与 forward 不自动判断"是否真正送达"——发送/转发后会逐条截图存档，session 结束自动生成 outputs/<session>/review.html 供人工快速复核。

怎么打开：运行结束时日志会打印 review.html 路径。在「访达 (Finder)」里双击该文件，或在终端执行 open outputs/<session>/review.html，即用默认浏览器打开。

验收什么：

  • forward：逐人核对微信名 ↔ 微信号 ↔ 选中截图是否一致，以及每人的「微信号有效 ✓/✗」标记（按 CSV 行号关联检测截图）
  • send：逐条核对发送截图与消息内容是否对得上
  • 报告只是辅助核对；最终是否送达，仍需在微信里人工确认收件人确实收到了卡片/消息

review.html 由 python3 生成。目标机若没装 python3，发送/转发照常完成，只是跳过该报告——send 可换一台有 python3 的机器用 make send-review SESSION=<目录> 补生成。

常见问题

Q: 运行时提示二进制“已损坏/无法打开”

A: 这是 macOS 的 Gatekeeper/隔离属性（quarantine）导致的，并非程序逻辑错误。 从网络下载解压的发布包，其内的二进制（bin/wca-*）会被打上隔离属性。 对整个解压目录清除一次即可（路径替换为你实际解压后的目录）：

xattr -dr com.apple.quarantine /path/to/wechat_automation

执行后重新在终端运行 ./wechat_auto.sh invite <csv>。 如果仍被拦截，可到“系统设置 → 隐私与安全性”里点击“仍要允许”。

Q: 截图检测全部显示桌面壁纸 / suspect 检测不准

A: 终端应用缺少屏幕录制权限。打开 系统设置 → 隐私与安全性 → 屏幕录制，勾选您使用的终端应用，然后 重启终端 再运行。

Q: 提示"微信没有可用窗口"

A: 请确保微信主窗口已打开，不要用 Command+W 关闭所有窗口。

Q: 提示"用户不存在"

A: 检查 CSV 中的 wechat_id 是否正确，确保该用户在您的好友列表中。

Q: 提示"没有辅助功能权限"

A: 工具在启动自检时会显式检查辅助功能权限，并提示"请到 系统设置 → 隐私与安全性 → 辅助功能，勾选 WeChat（或运行本工具的终端）后重试"。按提示授权后重新运行即可（也可参照上述"授予权限"步骤）。

Q: 邀请失败率较高

A: 可能原因：

  • 网络延迟：增加延迟参数（如 3 6）
  • 微信窗口大小：建议使用标准窗口尺寸（约 1200x800）
  • 操作过快：微信可能认为是异常行为

Q: 如何处理失败的任务？

A: 查看 failed_tasks_YYYYMMDD.csv，修正后重新运行该文件。

注意事项

⚠️ 重要提醒：

  1. 建议单账号每天邀请不超过 100 人——这是经验值，工具本身不做限制
  2. 运行期间不要操作鼠标键盘
  3. 确保微信窗口在主显示器上
  4. 首次使用建议测试 2-3 个任务
